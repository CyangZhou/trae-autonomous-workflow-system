# 知识蒸馏器 (Knowledge Distiller)

> 让复杂知识变得简单易懂

---

## 一、技能概述

### 1.1 核心能力

```
搜索 → 整理 → 蒸馏 → 费曼化
  ↓       ↓       ↓        ↓
获取    归纳    提取     通俗化
```

### 1.2 触发场景

| 触发词 | 动作 |
|:---|:---|
| 学习、研究、了解 | 启动知识蒸馏流程 |
| 搜索并整理 | 搜索 + 归纳 |
| 蒸馏、提炼 | 提取核心知识 |
| 费曼、通俗化 | 转化为易懂文档 |
| 解释一下、讲清楚 | 费曼学习法输出 |

### 1.3 输出标准

```
✓ 全篇难易度一致
✓ 无复杂专用术语（或已解释）
✓ 通俗易懂
✓ 结构清晰
✓ 有具体例子
```

## 三、费曼学习法实现

### 3.1 费曼四步法

```
Step 1: 选择概念
  → 明确要解释的知识点
  → 界定范围和深度

Step 2: 假想教学
  → 想象向小学生解释
  → 用最简单的语言
  → 避免专业术语

Step 3: 发现漏洞
  → 找出解释不清的地方
  → 标记需要补充的知识
  → 返回搜索填补空白

Step 4: 简化提炼
  → 用类比简化复杂概念
  → 用例子说明抽象原理
  → 确保全篇难易度一致
```

### 3.2 通俗化原则

```
原则 1: 一句话定义
  每个概念先用一句话说清楚

原则 2: 生活类比
  用日常生活中的例子解释

原则 3: 层层递进
  从简单到复杂，循序渐进

原则 4: 术语解释
  必须使用的术语要解释

原则 5: 例子驱动
  每个要点配一个例子
```

### 3.3 难易度校准

```
检查清单:
  □ 是否有未解释的术语？
  □ 是否有过于复杂的句子？
  □ 是否有跳跃的逻辑？
  □ 是否缺少必要的例子？
  □ 全篇风格是否一致？

校准方法:
  → 读一遍，假装自己是门外汉
  → 标记所有不理解的地方
  → 修改直到通顺易懂
```

## 四、搜索策略

### 4.1 关键词优化

```
基础搜索:
  "{主题} 是什么"
  "{主题} 入门"
  "{主题} 教程"

深度搜索:
  "{主题} 原理"
  "{主题} 案例"
  "{主题} 最佳实践"

验证搜索:
  "{主题} 误区"
  "{主题} 对比"
  "{主题} 最新发展"
```

### 4.2 多源验证

```
优先级:
  1. 官方文档/权威来源
  2. 专业博客/技术文章
  3. 教程/课程
  4. 论坛讨论

交叉验证:
  → 至少3个来源确认关键信息
  → 有矛盾时标注不同观点
  → 不确定的信息标注"待验证"
```

## 五、输出模板

### 5.1 标准结构

```markdown
# {主题} - 通俗解读

> 一句话总结：{核心概念的一句话解释}

---

## 这是什么？

{用最简单的语言解释，配生活类比}

## 为什么重要？

{说明意义和价值，配具体场景}

## 怎么理解？

### 核心要点 1：{要点名称}
{解释 + 例子}

### 核心要点 2：{要点名称}
{解释 + 例子}

### 核心要点 3：{要点名称}
{解释 + 例子}

## 常见误区

- ❌ 误区1：{错误理解} → ✅ 正确理解：{正确解释}
- ❌ 误区2：{错误理解} → ✅ 正确理解：{正确解释}

## 实际应用

{具体的应用场景和案例}

## 总结

{用3句话总结核心内容}

---

*本文使用费曼学习法编写，力求通俗易懂*
```

### 5.2 术语处理

```
首次出现术语:
  {术语}（简单解释：{一句话说明}）

术语表格式:
  | 术语 | 通俗解释 |
  |:---|:---|
  | {术语} | {一句话解释} |
```

## 六、质量检查

### 6.1 蒸馏质量

```
检查项:
  □ 是否提取了核心知识？
  □ 是否去除了冗余信息？
  □ 是否保留了关键细节？
  □ 结构是否清晰？
```

### 6.2 费曼质量

```
检查项:
  □ 小学生能看懂吗？
  □ 术语都解释了吗？
  □ 有足够的例子吗？
  □ 全篇难易度一致吗？
```

### 6.3 完整性检查

```
检查项:
  □ 是否回答了用户的问题？
  □ 是否覆盖了主要方面？
  □ 是否有遗漏的重要信息？
  □ 是否标注了不确定的内容？
```

## 七、使用示例

### 示例 1：学习新技术

```
用户: "帮我学习一下 Docker 是什么"

执行流程:
1. 搜索: "Docker 是什么"、"Docker 入门"、"Docker 原理"
2. 整理: 提取核心概念、关键特性、应用场景
3. 蒸馏: 容器化、镜像、仓库三个核心
4. 费曼: 用"集装箱"类比解释容器化

输出: 通俗易懂的 Docker 入门文档
```

### 示例 2：理解复杂概念

```
用户: "解释一下量子纠缠"

执行流程:
1. 搜索: "量子纠缠 通俗解释"、"量子纠缠 原理"
2. 整理: 物理原理、实验验证、应用前景
3. 蒸馏: 纠缠态、非定域性、量子通信
4. 费曼: 用"魔法硬币"类比解释纠缠

输出: 面向大众的量子纠缠科普文档
```

## 八、注意事项

### 8.1 必须遵守

```
M1 - 搜索优先: 遇到不确定的内容必须搜索验证
M2 - 多源验证: 关键信息至少3个来源确认
M3 - 术语解释: 所有专业术语必须给出通俗解释
M4 - 例子驱动: 每个要点必须配例子
M5 - 难易一致: 全篇保持统一的易懂程度
```

### 8.2 禁止行为

```
N1 - 禁止臆造: 不确定的内容不能编造
N2 - 禁止术语堆砌: 不能使用大量未解释的术语
N3 - 禁止跳跃: 不能省略必要的解释步骤
N4 - 禁止风格不一: 不能前半篇简单后半篇复杂
```
